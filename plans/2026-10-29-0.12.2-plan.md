### タスク C：サンドボックス内ローカルコマンドの自動実行

**前提（B の結果の上で）**：`protocol.dart` は B が `runCommand.description` を書いたもので始める。

**触るファイル（変更してよい範囲）**
- `lib/core/protocol.dart`（`ToolApproval.needsApproval` と `SandboxPolicy`、`ToolCallParser._parseRunCommand`）
- `lib/mcp/mcp_tools.dart`（`ShellSettings.confirm`、`McpTools.approvalRequired`、`McpTools._runShell` の `badge` と `detail`）
- `lib/services/settings.dart`（`shellConfirm` の既定値と移行）
- `lib/ui/settings_page.dart`（「すべてのコマンドを実行前に確認する」の説明文）
- `android/app/src/main/kotlin/ai/arce/app/linux/LinuxEnv.kt`（**コメントのみ**：`proot is not a sandbox` の記述を、`/workspace` と rootfs の中に収まるコマンドは確認なしで走る、に合わせる）
- `test/core/tool_approval_test.dart`（`SandboxPolicy` のテスト）

**満たすこと**
1. `run_command` の引数 `auto_execute`（bool、既定 `true`）を追加。`false` なら必ず承認カードを出す。`ToolCallParser._parseRunCommand` は bool 以外を `ParseInvalid` にする。
2. `SandboxPolicy.isInsideSandbox` は、`cwd` の禁止先（`/sdcard`・`/storage`・`/mnt`・`/data/data`・`/data/user`・`/data/app`・`/system`・`/vendor`・`/apex`）、`..` で `/` を超えるパス、コマンド文字列中のホスト側パスをすべて `false` にする。`..` は解決してから判定する。
3. `McpTools.approvalRequired` は `run_command` のとき、`shell.confirm` が `true` なら承認、そうでなければ `SandboxPolicy` の判定に従う。`ShellSettings.confirm` の既定は `false`。
4. `AppSettings.shellConfirm` の既定は `false`。**0.12.1 で保存された `true` を引き継がない**よう、読み込み時は `shellConfirmAlways` キーがあるときだけその値を使い、無ければ既定の `false`。
5. 結果の `ToolActivity` に「自動実行だったか」を `badge` に出す（`自動実行 · exit 0 · 1.2秒`）。stdout/stderr は `detail` に入れ、モデルに返す本文は変えない。

**やってはいけないこと**
- `LinuxEnv.kt` の実行ロジックを変えない（コメントのみ）。変えると 15.10 の前提が崩れる。
- `proot is not a sandbox` の記述を「完全なサンドボックスである」に書き換えない。**パスと作業フォルダがアプリの外に漏れないこと**だけを保証する。
- `shellConfirm` を `AgentSettings.specs` に入れない（`blocked` のまま。理由：チャットから確認を外せてしまう）。
- 既存の `linux_env_test.dart` を壊さない。

**確認**
- `flutter analyze`、`flutter test test/core/tool_approval_test.dart test/services/linux_env_test.dart`

### タスク A：「実行する」押下時の即時フィードバック

**満たすこと**
1. `ChatController.answer()` で、承認カードの実行が終わるのを待たずに、**最初の `await` より前**に (a) 承認カードを閉じる（`state.task` を `TaskState.generation` にし、`pendingQuestion`・`pendingTool`・`pendingSettings`・`pendingProvider` を `null` にする）(b) ユーザーの回答（「実行する」など）をチャットに積む (c) `RunMeter.begin()` する。
2. 承認カードが**処理中でも押せない**よう、`QuestionCard` に押下直後のスピナー（`実行しています…`）を出す。
3. 下部バーを `chat.state.isGenerating` ではなく `app.chat.isRunning` で切り替え、ツール実行中も「停止」になる。
4. `_finishWith` で `meter.end()` し、値を `UiMessage`（`elapsedMs`・`promptTokens`・`completionTokens`・`requests`）に写す。

**やってはいけないこと**
- `answer()` の「承認しない」経路（`承認しない` の言葉をモデルに返す文面）を変えない。
- 停止の扱い（`_stopRequested`）を消さない。**承認後の停止**も今までどおり効くこと。
- `AskUser`（`ask_user` の質問タイル）の即時回答（自由入力）の動きを変えない。

**確認**
- `flutter test test/core/chat_controller_test.dart`（`pressing 実行する immediately ...` が緑）

## 5. 集計のルール

1. 各タスクの結果は、`flutter analyze` の件数（種類）・`flutter test` の件数・**変更したファイルの一覧**で集計する。
2. 集計のあと、失敗が 1 つでもあれば、**そのタスクに `revise` で返す**（依頼の文面に `revise: dN` を付ける）。直さないまま次へ進まない。
3. 全タスクが緑になったら、`docs/` の 19.5 に**実機の確認項目**を追記し、`main` へ fast-forward する。
4. `main` への fast-forward は、**5 つの OS のリリースが緑になってから**（AGENTS.md）。
