現行の未解決だけを書く。解決したものは書かない。

## 利用者の判断待ち
- **道 A（`http_request`）に足せる案**：秘密ごとに差し込める場所（ヘッダだけ・クエリだけ・本文も、など。本文やパスに入れると、許可したホストの中で別の場所に値を書き込めてしまう）、パスとメソッドの範囲、使う回数の上限、プロバイダ用の「鍵を作る管理用のパス」の拒否。どれを入れるか（`secrets`）。
- **「一覧とレート制限を返す API」**：Gemini の `models.list` / `models.get` の Model リソースの項目は、`name`・`version`・`displayName`・`description`・`inputTokenLimit`・`outputTokenLimit`・`supportedGenerationMethods`・`thinking`・`temperature` など。**レート制限・割り当て・無料枠の項目は見つからなかった**（検索の抜粋で確認。`ai.google.dev` は、この環境のネットワークで開けず、公式のページは直接読めていない）。レート制限は、公式の資料では AI Studio の画面で見る、と書かれているのみ。**一覧とレート制限を返す API の名前か URL を教えてもらえれば、それに合わせて作る**。
- **proot の中の `mcp` コマンド**：「proot に常に置いて、必要なときに MCP の内容を見て呼び出せるように」という指示を、アプリの 3 つの道具（`mcp_find`・`mcp_describe`・`mcp_call`。`integrations`）で実現した。proot の中に `mcp` コマンドを置く形は、承認カードを通らずに MCP の道具を呼べてしまうので、やっていない。「コマンドからも MCP を呼びたい」という意図が別にあるなら、教えてほしい（その場合は、`secrets` と同じく、コマンドごとの承認つきにする案）。
- **通信ログ**（こちらからの提案）：メタデータだけ（時刻・提供元・モデル・状態・時間・トークン数・フォールバック・エラー。本文とキーは持たない）を端末に残し、設定画面で見て・書き出せるようにする。モデルが読む道具は読み取り専用にする。メッセージ本文も記録するか（記録しないと再現が難しい／記録するとプライバシーが重い）の判断を待っている。返信の進み具合（`screens`）は、この途中の形（1 回の返信の中の数字だけで、保存しない）。
- **頼まれていないが、候補として挙げたもの**：コーディングモードの開発モデルを複数にする（済み）以外に、MCP のファイル結果の画像表示、会話タイトルの手動での変更（鉛筆アイコンは飾りのまま）、フォールバックで切り替わった分を通信回数に数える、`ci_status` のセルフホストの GitHub MCP（Actions の道具がある版）への切り替え、通知から会話を開くこと。
- **端末のモデルに渡す道具を減らすか**：道具の定義の合計は約 12,000 文字（`run_command` 2,154、`update_settings` 2,968（設定名の一覧を除いて約 2/3）、`shell_session` 1,543、`delegate` 1,532 ほか）。端末のモデルでは、これが最初の言葉までの時間の大半になる。端末のモデルには、`get_settings`・`update_settings`・`add_provider`・`ci_status`・`http_request`・`shell_session` などを渡さない、または説明を短くする設定（端末のモデルに渡す道具の選択）を足す案。どれを既定でオフにするかは、使い方によるので、利用者の判断を待っている。実機での、1 トークンあたりの読み込みの速さの測定も未。
- **旧ブランチの削除**：`archive` に履歴を残したので、`archive`・`dev`・`main` 以外の 15 本のブランチは、利用者が GitHub 上で削除してよい（`overview` の「履歴」に一覧）。この環境からは、ブランチの削除が拒否される。

## 実機での確認待ち（利用者の端末で試してもらう）

- **対話セッション**：`shell_session` で `python3` などを動かす。
- **`ci_status`**：「CI どう？」。
- そのほか：Gemini の 400（思考署名）、Markdown 描画・思考の見え方・折りたたみの見た目、停止ボタン、背景で続くチャット、通知、モデルの選択が再起動で戻らないこと、設定画面の予測変換、エラーの自動報告（設定にトークンを入れて「テスト送信」）、分担の実際の動き、設定画面のグリッドの見た目（`あふれ以外の見た目のずれは、機械では見つけにくい。実機の画面を教えてほしい`）、最適化（ストリーム・スクロール・Markdown の読み直しの減らし方）の効果（frame 時間は測っていない）。
