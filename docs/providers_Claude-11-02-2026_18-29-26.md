# クラウドのモデル（プロバイダ）

現行の仕様だけを書く。**未確認**は、実機・実際の API で確かめていない。公式の資料にこの環境から届かなかったものは、そう書く。

## 構成
- `AiProvider`（`lib/ai/provider.dart`。Flutter 非依存）が、`Delta`（本文・思考・ツール呼び出し・使用量・停止理由）の流れを返す。`openai_compatible.dart` が chat-completions の SSE を読む：chunk の境界で切れた行の復元、`reasoning_content`（または `reasoning`）の分離、分割で届く関数呼び出しの引数の組み立て、`usage`、`finish_reason`。接続先ごとの差は headers / body の上書きで吸収。失敗は日本語で原因別（応答の本文も保持する）。
- SSE の本文は `Utf8Decoder`（ストリーム版）で読む（chunk の境目で日本語の 3 バイトが切れても壊れない）。
- `CloudEngine implements InferenceEngine`：プロバイダを普通の推論エンジンとして扱う。`RoutingEngine` が、端末のエンジンとクラウドを要求ごとに振り分ける。`local` は予約 id（端末のモデルは、並んだプロバイダの 1 つ）。
- 決めたこと：
  1. プロンプトは **1 本の ChatML のまま**。どちらのエンジンでも同じものを作り、クラウドに送るときだけ `ChatMlBridge` がメッセージ列に分解する。
  2. **続行**は、書けている本文を最後の assistant メッセージとして送り、「その続きから書く。繰り返さない」という user メッセージを足す（OpenAI 互換の API には prefill の口が無いため）。
  3. **API キーは設定に持たせない**（`provider_key.<id>`、実体は `flutter_secure_storage`）。設定 JSON のコピーや QR で、キーは出ない。
  4. **黙って乗り換えない**：選んだプロバイダが失敗したら、その失敗を見せる（端末で答え直さない）。画面の回答元と、実際に答えた相手がずれないように（フォールバックは、設定したルールのときだけ。下）。
- **複数のプロバイダと、1 つに複数のモデル**：`ProviderConfig.models`（`ModelConfig { id, name, params, prompt, … }`）と、提供元ごとに選んだモデル（`providers.chosen`。古い保存の `providers.activeModel` も読む）。保存で動くのはその提供元の選択だけ（そのモデルが消えたときに限り、最初のモデルに戻る）。別の提供元へ行って戻っても、選んだモデルが残る。
- **ツールをクラウドへ渡す**：`GenerateRequest.tools`。`provider.capabilities.tools` が false のときは送らない。
- **思考**：クラウドは `reasoning_content` を読んで `<thinking>` として流す。モデルが返さない場合（`deepseek-chat` のような非 reasoning モデル）は出ない。端末は、速度⇔精度が 0.25 未満だと思考しない。続行の返信は思考を飛ばす。

## モデルごとの上限と、公式の推奨
- `ModelConfig` に**コンテキスト長**（`contextTokens`）と**最大出力**（`maxOutputTokens`）。
- 最大トークンの決め方（強い順）：**モデルごとの設定 ＞ 設定画面でユーザーが決めた値 ＞ 公式の推奨 ＞ そのモデルの最大出力（提供元の一覧から取得したもの。設定 `onlineUseModelMax`、既定オン） ＞ アプリの既定（全モデル共通）**。つまり、何も決めていないオンラインのモデルは、共通の 2048 に縛られず、モデルごとに返せる最大の長さで頼む（Gemini の無料枠のモデルも 65,536 など。`max_tokens` は上限であり、使った分だけ課金される）。端末のモデルには効かない。結果は、モデルの最大出力と、文脈に残った分（コンテキスト − 入力の見積もり − 512）に収める。temperature・top_p も同じ順。ユーザーが選んだ小さい値は下限で持ち上げない。アプリの既定の `effectiveMaxTokens` は `maxTokens × (0.5 + 速度精度)`。モデルごとの最大トークンの上限は 1,048,576。
- **公式の推奨があるのは、モデルカードのあるバージョンだけ**（`lib/ai/model_hints.dart`。メーカーのモデルカードだけを根拠にし、記述のあるバージョンにだけ使い、ユーザーが何も決めていない所にだけ使う。コードと docs に出典を書く）：DeepSeek V4／V4.1（temperature 1.0・top_p 1.0・max_tokens ≥ 256K・文脈 1M）、GLM-5 以降（temperature 1.0・top_p 0.95・最大 64K〜128K）。それ以外は従来どおり。モデルの編集の「公式の推奨を入れる」で値が入る。
- **自動取得**：①プロバイダの `GET /models`（**Gemini は、OpenAI 互換の一覧には id しか無いので、Gemini 自身の一覧 `GET /v1beta/models` を読む**。`inputTokenLimit`・`outputTokenLimit` がモデルごとに付く。使えるモデルの確認と同じ一覧で、同時に頼まれても 1 回だけ読む）（文脈＝`context_length`・`context_window`・`max_context_length`・`max_model_len`・`inputTokenLimit`、出力＝`top_provider.max_completion_tokens`・`max_completion_tokens`・`outputTokenLimit`、画像・ツールの対応。**曖昧な `max_tokens` は読まない**）、②Hugging Face の `config.json`（モデル名が `owner/name` のとき、文脈長だけ。`max_position_embeddings`、`text_config` の中も読む。**モデル名だけ**を送る。設定でオフにできる）。いつ：使い始めたとき（モデルごとに 1 回）、プロバイダの「取得」、モデルの編集の「上限を取得」。**ユーザーが入れた値は、自動では消さない**。
- 根拠にした公式：DeepSeek V4.1 Flash のモデルカードと `encoding/README.md`、`deepseek-ai/deepseek-recipe`（既定の max_tokens は 8192／65536／131072）、GLM-5.3 のモデルカード。「DeepSeek Harness」（`deepseek-ai/deepseek-harness`、`dsh`、MIT、developer preview）は agent を動かす側で、アプリが従う通信の仕様書ではない。`HenryZ838978/deepseek-harness` は非公式の再実装、`deepseekharness.dev` など公式を名乗るサイトの数字は根拠にしない。

## 思考（推論）をプロバイダへ届ける
モデルごとに**「思考の送り方」**（モデルの編集 →「思考（推論）」）。**既定は「送らない」**（提供元の既定で動く。DeepSeek も GLM も既定で思考する）。この間、チャットの思考スイッチはこのモデルに届かない（トーストで伝える）。

| 送り方 | 足す項目 |
|---|---|
| DeepSeek の API | `thinking: {type: enabled/disabled}`、思考オンなら `reasoning_effort` |
| Z.ai の API（GLM） | `thinking: {type, clear_thinking}`、思考オンなら `reasoning_effort` |
| chat template のサーバー（vLLM・SGLang・Together・DeepInfra など） | `chat_template_kwargs: {thinking, enable_thinking, thinking_mode, reasoning_effort, clear_thinking}` |
| OpenAI の形 | `reasoning_effort`（low/medium/high。max は high。オフは表せないので足さない） |
| OpenRouter の形（`ThinkingFormat.openRouter`） | `reasoning: {effort: low\|medium\|high}`、オフは `reasoning: {enabled: false}`。**リクエストの形は未確認**（公式 docs を開けず。違えば「追加のリクエスト項目」で上書き） |
| 送らない | なし |

- 思考のオン/オフ：自動（チャットのスイッチと速度⇔精度に従う。速い側の端はオフ）／常にオン／常にオフ。推論の強さ：入れた値が先（`low`/`high`/`max` または 1〜100）、空欄はスライダーから（0.5 未満 `low`、0.85 未満 `high`、以上 `max`）。
- GLM の `clear_thinking`：GLM-5.3 のモデルカードが「チャットでは true を明示」と書いているので、GLM の「おすすめの送り方を入れる」は true を入れる。「おすすめの送り方を入れる」は名前から選び（`owner/name` は vLLM 系 → chat template、素の名前はメーカー自身の API）、**ボタンを押したときだけ**入る。
- 項目は、生成した項目のあと・プロバイダの「追加のリクエスト項目」より前に入る。同じ名前は、プロバイダの上書きが勝つ。
- コーディングモードの役は思考のスイッチを持たないので、「自動」を「思考オン（スライダーは中ほど）」として扱う。
- **入力欄の「思考」ボタン**（`lib/ui/thinking_sheet.dart`）：押すとシートが開く。オンラインのモデル：「考える量」（オフ／自動／その送り方が書いている強さ：DeepSeek・Z.ai は 低・高・最大、そのほかは 低・中・高）、「送り方」（`ThinkingFormat`）、送り方が未設定のときは提供元のアドレス・モデル名からの推測のボタン。選ぶと、そのモデルの `ThinkingConfig` に保存される。端末のモデル：思考のスイッチと、速度⇔精度のスライダー。送り方を変えると、新しい形が知らない強さ（DeepSeek の `medium` など）は外れる。
- 思考の表示：返信の上の「思考プロセス」は、既定で開いたまま（設定 `thinkingExpanded`。オフにすると、返信が始まったあとは折りたたむ）。見出しに文字数を出す。

## ツールの会話の形と、思考を返す
- モデルごとの**「ツールの送り方」**：自動（既定。提供元が対応していれば function calling、していなければテキスト形式）／function calling（`tools` に定義、呼び出しは `tool_calls`、結果は `tool` メッセージ。システムプロンプトから `# Tools` の説明を外す）／テキスト形式（Qwen 形式。`tools` は送らない）。どちらでも、ツールの説明は 1 回だけ。端末のモデルの会話は変わらない（変換は provider に渡す直前の `ChatMlBridge` だけ）。結果が返らなかった呼び出し（途中で止めた会話）は、テキストに戻して送る。
- **思考を返す**：各返信の思考を `AssistantTurn.reasoning` に残し（DB schema 3）、プロンプトの文字には入れず、`GenerateRequest.assistantReasoning` を通して provider の assistant メッセージの `reasoning_content` にする。モデルの設定「過去の思考を返す」：自動（DeepSeek・GLM で、ツールが function calling のとき）／常に返す／返さない。根拠は、DeepSeek の `encoding`（ツールを宣言すると過去の思考を全部残す）と、GLM の `clear_thinking: false`。
- **1 回のラウンドで実行する道具は 1 つ**。1 つの返信に複数の呼び出しがあれば、最初の 1 つを実行する。
- **Gemini の複数の呼び出し**：Gemini の OpenAI 互換エンドポイントは、1 つの返信で複数の道具を呼ぶとき、すべての呼び出しの `index` を 0 にして、`id` だけで区別する（実機のエラーから分かったこと。公式の仕様は確認できていない）。`openai_compatible.dart` は、同じ `index` に**別の `id`** が来たら別の呼び出しにする。`id` も無く、つながって届いたものは、同じ道具の引数として `{...}{...}` を分ける（`splitObjects`。文字列の中の括弧は数えない）。読めなかったときのエラーには、本文の冒頭 120 文字も出す。
- **Gemini の思考署名**：Gemini 3 系は、道具の呼び出しに暗号化された**思考署名**を付けて返し（`tool_calls[].extra_content.google.thought_signature`。出典：VS Code の issue https://github.com/microsoft/vscode/issues/296713 、Google の開発者フォーラムの報告。公式 docs はこの環境から開けず、**フィールドの形・ストリームでの位置は未確認**）、次のリクエストでそれを返さないと 400 になる、という報告が複数ある。呼び出しに付いた `extra_content` を**そのまま**取っておき（`ToolCallDelta.extraContent`。履歴の呼び出しの JSON の `extra_content`）、次の送信の `tool_calls` にそのまま入れる。署名の無い提供元には何も足さない。**これで直るかは未確認**。Gemini はエラーを `[{"error": {...}}]` とリストで包むことがあるので、リストの先頭を読み、形が分からなければ本文の頭 300 文字を出す。

## チャットからプロバイダーを追加する
- 道具 `add_provider`（`name`・`base_url`・`models`・`tools`）。呼ぶと確認カードが出て、「追加する」を押したときだけ保存する。保存は必ず**新しい id の追加**で、既存のプロバイダーは変えない。使用中のプロバイダーも切り替えない。追加されるプロバイダは、キャッシュ関係が常にオフ。
- **既存のプロバイダーを変える道具は作っていない**（編集は設定画面だけ）。チャットに紛れ込んだ指示で、API キーが保存済みのプロバイダーの URL を書き換えられると、キーが別のサーバーに送られるため。
- API キーの欄は無い（スキーマにも入れていない）。`base_url` に `user:pass@`・`?api_key=`・`#…` があれば拒否する。`/chat/completions` まで貼ってあれば落とす。ヘッダーと追加のリクエスト項目も、この道具では入れない。確認カードは URL をそのまま出す（キーを後で入れたときの送り先を、利用者が見て確かめられる）。
- http のままキーやトークンを送る設定には、MCP サーバーとプロバイダの編集画面に「このアドレスは暗号化されません」の警告が出る（家の中・localhost は出さない）。

## モデルの一覧・フォールバック・トークンの事前チェック
- **モデルの一覧（`catalog`）と、使うモデル（`models`）は別**。`catalog` は `/models` で取れた一覧（`ProviderConfig.catalog`、取得時刻 `catalogAt`）、`models` は上限・思考・プロンプトなどを設定した、使うモデル。一覧から選ぶと、`ProviderStore.selectModel` が `models` に写す。何百件もの一覧を、設定を持つ `models` に入れないため。
- **自動取得**：設定「モデル一覧を自動で読む」（`modelListAutoFetch`）と「再取得の間隔（時間）」（`modelListRefreshHours`）。起動時に、古くなった一覧を背景で読む。プロバイダを保存したとき（そのプロバイダの欄「一覧を自動で読む」が入っていれば）、すぐ読む。MCP サーバーを保存したときは、すぐ道具の一覧を読み（`probeMcp`）、その大きさ（トークン数の見積もり）を知らせる。
- **ツリー表示と検索**（`lib/ai/model_catalog.dart`、`model_tree.dart`、`lib/ui/model_tree_view.dart`）：モデル名の作者（`anthropic/`・`google/`・`deepseek-ai/` など、接頭辞）で分けて、Claude・Gemini・DeepSeek …の折りたたみにする。8 件以下の提供元は分けない。検索欄は大文字小文字を区別せず、空白で区切った語をすべて含むものが残る（`claude opus`）。提供元の名前にも当たる。検索中はすべての折りたたみを開く。コーディングモードの選択画面は、上に「最近使った」（`ProviderStore.recentRefs` 順。`markUsed` が返信を作るたびに記録。数は設定 `recentModelCount`、0 で出さない）と、提供元ごとのツリー。
- **フォールバック**（`lib/ai/fallback.dart`）：ルール `FallbackRule { from, targets, statuses }`。`from` と `targets` は `provider|model`、`provider|*`、`*` のどれか。具体的なルールが優先（モデル > 提供元 > `*`）。切り替える失敗の既定は 401・403・404・408・429、5xx すべて、接続の失敗。**返信の最初の 1 文字が来る前の失敗だけ**切り替え、書き始めたあとは切り替えない。切り替えると、チャットに「A が 403 のため B に切り替えました」と出す。設定「フォールバックを使う」（`fallbackEnabled`）で一括して止められる。コーディングモードの設計・開発の役割にも効く。
  - **ルールの編集は設定画面（詳細）だけで、チャットからは変えられない**。会話の内容が別の提供元に送られるため、チャットの指示で送り先を足されると、プロンプトインジェクションで会話が外に出せてしまう（`add_provider` と同じ理由）。
- **トークンの事前チェック**（`lib/ai/token_budget.dart`）：送る前に、指示とツール定義の長さを見積もる（UTF-8 のバイト数 ÷ 3。目安）。モデルの文脈（`contextTokens`）がわかるモデルだけ。(1) 指示＋ツールが文脈の「割合」（設定 `tokenOverheadPercent`、既定 80%）を超える、または (2) 会話＋余白 256 が文脈を超える、のとき、**送らずに**エラーにする。エラーには、どの MCP サーバーのツール定義が大きいかを含める。設定 `tokenPrecheck` で止められる。見積もりはモデルのトークナイザとは違うので外れうる。**実際のモデルとの照らし合わせは未**。
- **道具の呼び出しの繰り返し**：**同じ道具・同じ引数の呼び出し**が繰り返されたときだけ止める。ラウンドの上限（`maxToolRounds`）は暴走の安全弁で、既定 30、最大 200。
- **「詳細」画面**（`lib/ui/model_detail_page.dart`）：提供元ごとの一覧の取得、フォールバックのルール、トークンの事前チェック、MCP のコストの確認、使えるモデルの確認。入口は、モデルの一覧のシートと、思考のシートの「モデルの詳細設定」。
- 表示：「ローカルモデル未導入」（端末のモデルが無いとき。オンラインのモデルを使っているときは、そのモデルの名前を出す）。

## プロンプトのキャッシュと使用量
- **提供元の側の仕組み**：OpenAI 形式の提供元の多くは、**同じ先頭（system → 道具 → 会話）**を続けて送ると、その分を自動でキャッシュから読み、安くて速くなる（OpenAI は 1,024 トークン以上、DeepSeek も自動）。アプリが送る側でできるのは、先頭を変えないこと。プロンプトに時刻などの毎回変わる文字は入っておらず、会話は後ろに足すだけなので、同じ会話の中では先頭が安定している（`ChatMlPromptBuilder`・`ChatMlBridge`）。先頭が変わるのは、(1) エージェントが変わったとき（メッセージごとに選び直すので、役割の指示が変わる）、(2) 設定（口調・追加の指示・最大文字数）やモデルを変えたとき、(3) 会話を要約したとき（`core_engine`）。
- **読むもの**：応答の使用量（`usage`）から、キャッシュで読まれたトークン数を書いてあれば読む：`prompt_tokens_details.cached_tokens`（OpenAI 形式）、`prompt_cache_hit_tokens`（DeepSeek 形式）。無ければ「分からない」（0 とは別）。`UsageDelta.cachedTokens` → `Usage`（`GenerationEvent`）→ `RunMeter.usage` → 返信の進み具合の行に **「入力 12,340 トークン（キャッシュ 9,800）」**。端末のモデルと、使用量を返さない提供元は、この表示が出ない。分担の開発モデルの分は数えない。
- **送るもの（`prompt_cache_key`）と on/off**：プロバイダごとのスイッチ **「プロンプトのキャッシュ用の印を送る」**（プロバイダの編集画面。`ProviderConfig.promptCache`。**既定はオフ**：知らない項目を 400 で断る互換サーバーがあるため）。**オン**のときは、同じ会話のリクエストすべてに、同じ**印**（`arce-` と 16 桁のランダムな文字。ユーザーや本文の情報は入らない）を、項目名 **`prompt_cache_key`**（プロバイダごとに変えられる。`model`・`messages`・`tools` など元からある名前と、英数字以外は保存のときに断る）で付ける。印は会話を始めたときに作り、会話が保存されて ID が付いても変えない。履歴から開き直したときは `arce-<会話の ID>`、新しい会話は別の印。**オフ**のときは、キャッシュ関係のものを何も送らない。
  - 画面の文にも書いてある注意：**OpenAI・DeepSeek・Gemini などの提供元が自分で行う自動のキャッシュは、このスイッチを切っても止まらない**（アプリが送るものを切り替えるだけ）。
  - **安全網**：サーバーが 400 か 422 でその項目名を挙げて断ったら、1 回だけ項目なしで送り直し、そのプロバイダのスイッチをオフにして、トーストで理由を知らせる（項目名を挙げない 400 では何も変えない。利用者が「追加のリクエスト項目」に同じ名前を書いていたときも変えない）。
  - **チャットからは変えられない**（プロバイダの設定は、チャットでは追加 `add_provider` しかできない）。全体の既定は置かない（提供元ごとに対応が違う）。Anthropic の `cache_control` は、OpenAI 形式の窓口では使えないので**未対応**。
- **未確認**：実際の OpenAI・Gemini の応答（400 の文面は偽のサーバーで再現した）、この印で本当に当たりが良くなるか。OpenAI（`platform.openai.com`）と DeepSeek（`api-docs.deepseek.com`）の公式ドキュメントは、この環境のネットワークでは名前を解決できず、読めなかった（項目名は、公式の説明を覚えている範囲のもの）。Gemini の OpenAI 互換の窓口が、キャッシュの数を `usage` のどこに出すかも確認できなかった（Google の標準の応答では `cached_content_token_count`。https://ai.google.dev/gemini-api/docs/caching）。読めない形なら、表示が出ないだけで、動作には影響しない。

## このキーで使えないモデルの確認と印
プロバイダのモデル一覧（`/models`）は、そのキー（プラン。たとえば Gemini の無料枠）で使えないモデルも含む。使えないモデルを選べないようにする、のではなく、印を付けて分かるようにする。
- **分類**（`lib/ai/model_availability.dart`）：失敗の応答（HTTP の状態と本文）から、**使える／使えない（このキーやプランでは無理）／一時的／キーが拒否された／判断できない**の 5 つと、短い日本語の理由を決める。ステータスコードを先に見て、本文のどのサービスでも使う言い回しで補う。「使えない」にするのは、`limit: 0`、OpenAI 形式の `insufficient_quota`、403 の権限なし、404 でモデル名が出ているとき、など。Gemini の「利用枠を超えました」の一文は、1 分あたりの制限でも出るので、**この一文だけでは「使えない」にしない**（一時的）。401 は、モデルではなくキーの問題。
- **確認の対象**は、いま設定しているモデルだけ：答えるモデル、コーディングモードのプランナー（固定のとき）と開発モデル、タイトル用のモデル（ローカルは対象外、同じモデルは 1 回）。
- **流れ**（`AppController.checkModels`）：
  1. **そのキーで読めるモデル一覧を取る**（`OpenAiCompatibleProvider.fetchKeyModels`）。Gemini の端点なら Gemini 自身の一覧 `GET https://generativelanguage.googleapis.com/v1beta/models?pageSize=1000`（キーは `x-goog-api-key`、`nextPageToken` で続きを読む。各モデルの `supportedGenerationMethods` とトークンの上限が付く）、それ以外は OpenAI 形式の `/models`。1 回の取得で、回数制限に数えられず、問い合わせも送らない。
  2. **一覧にないモデル**、**一覧が「チャット（generateContent）に対応しない」と言うモデル**（埋め込みなど）は、「使えません（理由）」にして印を付ける（`ModelListCheck`）。
  3. **一覧にあるモデルは「一覧にあります」**。**これは「使える」ではない**（無料枠は、使えないモデルも一覧に載せる。回数の制限は、一覧では分からない）。印は付けず、あとで実際に送って「このキーでは使えない」と返れば、印が付く。
  4. 一覧が読めない・空のときは、短い問い合わせ（「hi」を 1 回、`max_tokens` 1、ツールなし）で確かめる。
  5. 設定 `modelCheckAsksToo`（既定オフ）をオンにすると、一覧にあるモデルにも短い問い合わせを 1 回送る（無料枠で使えないモデルまで分かる。回数を使う）。
  - キーが拒否されたとき（401・403）は、その旨を 1 回だけ言い、モデルの印は付けない。
  - モデルの一覧のシートの「設定中のモデルを確かめる」は、一覧を毎回読み直し、モデルごとに「使えます／使えません（理由）／一覧にあります／判断できませんでした」を言う。
  - モデルを選んだときは、設定 `autoCheckSelectedModel`（既定オン）で、その 1 つを同じ流れで確かめ、使えないと分かったら「〜は、このキーでは使えない可能性があります（理由）。別のモデルを選んでください」と知らせる（印が新しいときは確かめない。起動時には確かめない。一覧は、プロバイダの設定が変わるまで覚えている）。
- **自動の印**：実際の送信が「このキーでは使えない」で失敗したら、そのモデルに印を付け、エラー文に「どのモデルが・なぜ・別のモデルを選んで」を出す。後でそのモデルが答えれば「使える」に戻る。
- **記憶**（`lib/services/model_availability_store.dart`）：提供元・モデルごとの「使える／使えない」・短い理由・時刻だけ（キーも、やり取りの内容も保存しない）。設定の日数（既定 7 日）で期限切れ（プランは変わるため）。「印をすべて消す」ボタンもある。
- **見え方**：モデルのすべての一覧（チャットの切り替え、プロバイダのモデル一覧、コーディングモードの選択、フォールバックの選択）で、使えないモデルは灰色・理由つきの印（⊘）・同じ折りたたみの最後。**灰色でも選べる**（プランが変わっていることがあるため）。使えると確認できたモデルには ✓。確認していないモデルには何も出ない。設定で隠すこともできる（使っているモデルは隠れない。フォールバックの「どのモデルが使えないとき」の選択画面だけは、使えないモデルこそ対象なので隠さない）。上のバーのモデル名のチップには、印を出していない。
- **設定**（モデルの詳細設定の「使えるモデルの確認」。チャットからも変えられる）：`hideUnusableModels`（既定オフ）、`markBlockedModels`（オン）、`autoCheckSelectedModel`（オン）、`modelCheckAsksToo`（オフ）、`modelProbeConcurrency`（3、1〜8）、`modelProbeTimeoutSeconds`（30、5〜120）、`modelAvailabilityTrustDays`（7、1〜90）。
- **未確認**：Gemini の `models.list` の address・`x-goog-api-key`・`supportedGenerationMethods` は、**公式の Gemini API 資料を読んだものではなく、記憶による**（この環境では公式の資料に届かず、無料枠の可否や残りの回数を返す公式の API も見つからなかった）。**本物の Gemini の応答は、一度も見ていない**（テストの応答は、各サービスの形に合わせて書いた）。言い回しが変わったら「判断できない」になり、印が付かないだけ。OpenAI の新しいモデルは `max_tokens` を受け付けず 400 になる（「判断できない」で、印は付かない）。確認の問い合わせも、無料枠の回数に 1 回ずつ数えられる。
