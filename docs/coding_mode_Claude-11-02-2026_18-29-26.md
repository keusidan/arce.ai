# コーディングモード（プランナーモデル＋開発モデル）

現行の仕様だけを書く。

**プランナーモデルが細かく分けて、複数の開発モデルに並列に渡す。アプリは呼び出しの手伝いだけをする。**

```
依頼（Coding エージェント）
  └ プランナー（入力欄で選んだモデル。固定もできる）が答える（道具・思考・停止・ストリーミングはふつうのチャットと同じ）
       ├ 小さな依頼・質問 → 自分で答える
       └ 大きな依頼 → 道具 delegate を 1 回呼ぶ
            plan（Mermaid の図）＋ summary（共通の決めごと）＋ tasks（id・題・指示・待つ相手）
                a["モデル"] ──┐
                b["API"]  ────┼──▶ d["画面"] ──▶ e["テスト"]      （矢印 a --> d ＝ d は a の結果を待つ）
                c["設定"]（待たない：すぐ始まる）
            待たない仕事は、空いている開発モデルへ**すぐ**渡る（モデル A・B・C … に分け合って同時に）
            待つ仕事は、前の仕事の**結果を渡されて**から始まる
         開発モデルは、聞かずに自分で決めて実装し、結果だけを返す
         結果は、番号（d1, d2 …）つきでプランナーに返り、図とファイルはユーザーに見える
       └ プランナーが読んで、本当に間違っていれば delegate を revise つきで呼ぶ／よければ短くまとめて終わる
```

## アプリがすること（`lib/ai/delegation.dart` の `DelegateRunner`）
1. 開発モデル（複数）とその上限を持つ。
2. 仕事を**空いたモデルへ順に**渡す（`_Pool`。1 つのモデルが同時に受ける数は、設定「1 つの開発モデルが同時に走らせる数」とモデルの上限の小さいほう。端末のモデルは 1）。いちばん空いているモデルを選び、全部埋まっていれば空くのを待つ。
3. **依存**を守る：矢印の先の仕事は、前の仕事が終わってから始まり、その結果（題と答え。長さは「プランナーが読む結果の長さ」まで）を、自分の依頼の前に付けて渡される。前の仕事が失敗したら、その先は**実行せず**「前の仕事 dN が失敗したため」と返す。
4. 結果に番号を付けて覚える（200 件まで）。`revise` は、元のタスク・前の答え・直す内容を渡し直す。
5. 図（プランナーが書いたもの。無ければ依存から描いたもの）とファイルを、プランナーの答えの途中に**そのままユーザーに見せる**（`ToolOutcome.shown`。Mermaid のコードブロック）。
6. **質問は返さない**：開発モデルが `QUESTION:` で答えたら、プランナーには聞かずに「誰も答えられない。いちばん妥当な選択で、完全なファイルを今出して」と**1 回だけ**伝える。それでも質問なら、その仕事を失敗として返す。
7. **失敗は別のモデルへ**：モデルが失敗（接続・空の答え）したら、その仕事を、まだ試していない別のモデルに渡す（1 回）。
8. 1 件が失敗しても、ほかの結果は返す。
9. 停止で全部の開発モデルを止める。

## 分割の図（`lib/core/plan_graph.dart`）
Mermaid の `flowchart` のうち「これが先、次にあれ」を言う部分だけを読む（節点 `a["題"]`・`a[題]`・`a(題)`・`a{題}`・`a`、矢印 `-->`・`---`・`==>`・`-.->`（ラベル付きも）、`a --> b & c`、`a --> b --> c`）。スタイル・subgraph などは読み飛ばす。**矢印 `a --> b` は「b は a の後」**。図とタスクの `depends_on` は合わせて使う。図が読めない（節点が無い）・図に載った id がタスクに無い・待つ相手がタスクに無い・**輪（循環）になっている**ときは、理由を付けて断り、プランナーに書き直させる。図は、ほかの道具（ローカルの opencode など）に**同じ文章のまま**渡せる形にしてある。

## 失敗でエラーにしない
プランナーが書いた道具の呼び出しが使えない（図が読めない・タスクに指示が無い・輪になっている・許可されていない道具など）とき、返信を**エラーで終わらせず**、「使えなかった理由」をアプリの注として伝えて書き直させる（`retryLimit` 回まで。画面には「道具の呼び出しが読めませんでした（理由）。書き直します」が出る）。回数を超えたら、理由を出して止める。ふつうの道具にも効く。開発モデルの失敗は結果として返り、全部失敗したときは「自分でやるか、もっと単純な仕事に分けて」とプランナーに伝える。

## アプリがしないこと
分け方を決める、結果の良し悪しを判断する、直させるかを決める。これらはプランナーの判断。アプリがプランナーに伝えるのは、道具の使い方と上限だけ（`CodingPrompts.plannerInstructions`）：小さな依頼は自分で答える／大きいときは delegate を 1 回／**細かい目標に分ける**（1 ファイルか関数のまとまり）／Mermaid の図で分ける・待たない仕事を増やす／同時に走る仕事は互いを見られないので名前・シグネチャ・データ形式は要約と各タスクに書く／開発モデルは聞かずに決める／ファイルはユーザーに見えるので答えに写さない／直す回数は N 回まで。

## どのモデルが答えるか（プランナー）
**既定は、入力欄で選んだモデル**（設定「プランナーは、使用中のモデルに合わせる」＝オン）。オフにすると、設定の**プランナーモデル**に固定され、そのときだけ Coding エージェントの依頼は固定のモデルが答える（`RoutingEngine.planner`）。固定にすると、入力欄でモデルを切り替えても Coding の依頼には届かない。`delegate` の道具とプランナーへの指示は、Coding エージェントで、コーディングモードが使えるとき（オン・開発モデルが 1 つ以上使える・プランナーが決まっている）だけ出る。役には、オンラインの各モデルも端末のモデルも選べる（`provider|model`、端末は `local|`）。

## 安くなる理由・速くなる理由
長いコードを書くのは開発モデル（安い・端末のモデルなら無料）。プランナーの出力は短い指示と確認だけ。開発モデルには、会話の全体ではなく**要約とそのタスク（と、待った相手の結果）**だけを送る。細かく分けて、複数のモデルで同時に書くので、速い。

## 端末のモデルの扱い
端末のモデルは同時に 1 つのチャットしか使えない（`ExclusiveLease`）。開発モデルの中に端末のモデルがあれば、`delegate` の実行の間だけ借りる。**ほかのチャットが使っていれば、そのモデルは使わず、ほかの開発モデルが仕事を受ける**（全部が端末のモデルなら、プランナーに「使用中」と返す）。分担の途中でアプリを最近使ったアプリから消すと、Android は画面と Flutter のエンジン（Dart のコード）を壊す（前面サービスはプロセスを残すが、Dart の仕事は続かない）。

## 設定
オン/オフ、プランナーは使用中のモデルに合わせる（既定オン）、プランナーモデル（オフのとき）、開発モデルと**追加の開発モデル**（`developerModelsMore`。1 行に 1 つ。設定画面では「開発モデルを追加」）、タスクの最大数（既定 **8**、最大 16。超えた分は断り、プランナーに伝える）、1 つの開発モデルが同時に走らせる数（既定 **4**）、書き直しの回数（既定 1。0 で「直させない」と伝える。伝えるだけで、数えて止めはしない）、開発モデルの最大トークン（**0 ＝ 自動**）、プランナーが読む結果の長さ（既定 12000 文字/件）。チャットの入力欄に「分担」ボタン。変えてよい項目は、チャットからも変えられる（`AgentSettings`）。

## 実装
`lib/core/coding_plan.dart`（設定・プロンプト・`questionIn`・`filesIn`）、`lib/core/plan_graph.dart`（図）、`lib/core/protocol.dart`（`delegate` の道具と読み取り・検査）、`lib/ai/roles.dart`（`RoleModel`）、`lib/ai/delegation.dart`（`DelegateRunner`・`_Pool`）、`lib/core/chat_controller.dart`（使えない呼び出しの書き直し）、`AppController`（`_plannerEngine`・`_developerRoles`・`_SessionToolRuntime`）。

## 同じ計画を、コマンドラインのエージェント（opencode など）に渡す
プランナーの指示に、「利用者が頼んだときは、同じ計画（図、そのあとに各タスクの指示とファイル）を `/workspace/PLAN.md` に書き、`shell_session`（一発で終わる使い方があれば `run_command`）でそのエージェントに渡し、終わるまで画面を読む。図が依存を表すので、その順に進めさせる」と書いてある（`CodingPrompts.plannerInstructions`）。Mermaid は多くの CLI エージェントがそのまま読める形なので、図を作り直す必要はない。**アプリが PLAN.md を自動で作る機能は無い**（書くのはプランナー）。**未確認**：opencode・agy（Antigravity CLI）が、この rootfs（Ubuntu 24.04 arm64、proot）に入って動くか、どう呼ぶのが正しいか（公式の資料に届かず、確かめていない）。

## 未確認・既知の制限
- **未確認**：実際のモデルで、プランナーが図とタスクの id を正しく合わせて書くか（小さいモデルは崩しやすい。崩したときは書き直しで直す）、複数の開発モデルでの実際の速さ、`QUESTION:` を返すモデルが「決めて」と言われたあとに作れるか、開発モデルの出力が長いときのユーザーへの見え方。
- Mermaid の図は、いまは**コードブロック**で見せる（図としての描画はしない。コピーして mermaid の表示器に貼れる）。
- トークンの使用量・費用の表示は、分担の開発モデルの分については無い。開発モデルの温度は 0.2 に固定（モデルの設定・メーカーの推奨があればそちらが優先。設定にするのは今後）。Coding エージェントのファイルの読み書きは、Linux 環境の道具（`run_command`・`shell_session`）で行う。
