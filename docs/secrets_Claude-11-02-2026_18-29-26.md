# 秘密の扱い：環境変数の `secrets` と、プレースホルダー `{{secret:ID}}`

現行の仕様だけを書く。**未確認**は、実機・実際の API で確かめていない。

## 方針
- キー・トークン（プロバイダの API キー、MCP のトークン、検索 API のキー、GitHub のトークン、自分で入れた値）は、**モデルにも、会話の履歴にも、承認カードにも、ログにも、通知にも、エラー文にも、バックアップにも出さない**。値は端末の安全な領域（`flutter_secure_storage`）にだけある。モデルは、名前（id）だけを知る。
- 渡し方は 2 つ：**プレースホルダー `{{secret:ID}}`**（API を呼ぶ。送り先を秘密ごとに固定できる）と、**環境変数 `secrets: ["名前"]`**（コマンドが値を読む。送り先は制限できない）。
- proot は境界ではない（`linux_environment`）ので、コマンドに渡した値は、そのコマンドがどこへでも送れる。**API を呼ぶだけなら `http_request`（道 A）。スクリプトで加工が要るときだけ道 B**。

## id（名前から作る）
- キーやトークンを持つ**すべての項目**に、名前から作った id が付く（`SecretIds`、`lib/core/secret_placeholders.dart`）：全角を半角に、英数字以外は `-`、日本語だけの名前は種類名（`provider`・`mcp` …）、重なれば `-2`。
- 対象：プロバイダの API キー・MCP のトークン・検索 API のキー・GitHub のトークン（更新用・エラー報告用の 2 つ）・入力した値（`SecretRegistry`、`lib/core/secret_book.dart`）。
- **送ってよいホスト**：プロバイダの `baseUrl`・MCP の URL・検索 API の URL のホストを**自動で**入れる。GitHub は `api.github.com`。入力した値は、利用者が書く（空なら、プレースホルダーでは使えない。`*` は「どこへでも」で、赤い警告）。
- 設定画面（設定 →「Linux 環境」→「秘密（モデルが {{secret:ID}} で使う）」。`lib/ui/secrets_widgets.dart`）：すべての項目を並べる（id を `{{secret:id}}` の形で、種類・送ってよいホスト・値があるか・使えない理由・「**モデルに使わせる**」スイッチ（`secretsOffForModel`。`provider:gem` のような安定した鍵で書く））。値は画面のどこにも出さない。入力した値は、タップで編集（名前は固定、値は空のままで変えない、ホストは 1 行に 1 つ）、✕で削除。その下に **`http_request` のカード**（使う・使わない、確認の方式（`never` は赤い警告）、http の許可（赤い警告）、応答の文字数、待ち時間、リダイレクトの回数、道 A と道 B の使い分けの説明）。検索の索引にも、すべての行を入れてある。
- **チャットからは、秘密の一覧・ホスト・「モデルに使わせる」を変えられない**（`blocked`。メッセージで送り先を足されると、キーが外に出る）。

## 共通の規則
- プレースホルダーの**文字が出てよい場所**は、`http_request` の引数、`run_command` / `shell_session` の `command`・`input` だけ。ほかの道具（検索・MCP の道具・設定の変更など）に書かれても、**差し込まない**（そのまま文字として渡る）。
- 名前が無い・値が空の秘密を書いたら、**実行せずに**「使える名前は、これ」と返す。
- 履歴に入るのは、モデルが書いた文（プレースホルダーのまま）だけ。

## 土台（`lib/core/secret_placeholders.dart`、`secret_book.dart`。純粋でテストが厚い）
- `SecretPlaceholders`：`{{secret:ID}}`（`\{\{\s*secret\s*:\s*([A-Za-z0-9][A-Za-z0-9_.\-]{0,63})\s*\}\}`。id は小文字にそろえる）。
- `SecretHosts.problem(url, allowed, {allowInsecure})`：https のみ（http は設定でオンにしたときだけ）、`user@host` 不可、空白・バックスラッシュ・制御文字不可、**`%` を含むホスト（`%2e` など）不可**、非 ASCII・IDN のホスト不可、**端末と内側のネットワークは常に不可**（`localhost`・単一ラベル・`.local` `.internal` `.lan` ほか・IPv4/IPv6 の私的アドレス（loopback・private・link-local・shared・reserved、`::ffff:a.b.c.d`）・整数/16 進/8 進の数字ホスト）、ホストは秘密に結んだものに入っていること（`*.example.com` は配下のみ。`example.com` 自身は含まない）。
- `SecretRedaction`：返すものすべてから値を伏せる（`[secret:id]` に置き換え）。**伏せる形**：値そのもの、URL エンコード（2 通り）、JSON のエスケープ（`\/` を含む）、`\uXXXX`、HTML 実体（10 進・16 進）、hex（小文字・大文字）、base64（標準・url-safe、padding あり・なし、長い文字列の中に値があるときの 3 つの位置の揃え方）。4 文字未満の値は伏せない（普通の文を壊すため）。base64 の断片は 8 文字以上のときだけ。**切れた末尾**：`trimTail` が真のとき、文の末尾が値の始まりなら、その部分も落とす（残りが次に届いて 2 つを足されないため）。
- `SecretRegistry`（`SecretBook`・`SecretSource`）：上の id の一覧と、値・ホストの引き当て。`stableKey`・`envName`（`ARCE_SECRET_<ID>`）を持つ。

## 道 A：`http_request`（アプリが通信する。送り先の保証がある）
`lib/mcp/http_request_tool.dart`。
- モデルが書くのは、`curl` に相当する内容だけ：`method`・`url`・`headers`・`body`（または `json`）・`timeout_seconds`。`{{secret:ID}}` は、URL の**ホスト部より後ろ**・ヘッダの**値**・本文だけ（ヘッダ名・スキーム・ホスト部は不可）。例：`Authorization: Bearer {{secret:gemini}}`、`https://…/models?key={{secret:gemini}}`。
- **アプリが差し込んで、アプリが送る**（proot は通らない）。差し込んだあとの**最終の URL のホストが、使う秘密すべての「送ってよいホスト」に入っているか**を確かめ、**入っていなければ何も送らず**、「この秘密は、そのホストには送れません」と返す。名前解決の結果が私的アドレスのときも送らない。
- **リダイレクト**：秘密を使うとき、**同じホストの https にだけ**、設定 `httpRequestMaxRedirects`（既定 5、0〜10）の回数まで追う（303 は GET にして本文を外す。別のホスト・http には追わず、そう返す）。
- **応答**：状態・content-type・content-length・retry-after・`ratelimit` 系のヘッダ・本文（設定の文字数で切る。`httpRequestMaxResponseChars`）。4xx/5xx は失敗扱い。**返すものすべて（本文・ヘッダ・エラー・ログ）から、値を伏せる**。**値を伏せてから長さで切り**、切れた末尾の値の書きかけは落とす。
- **承認**（`httpRequestConfirm`）：`secretOrWrite`（既定：秘密を使う、または GET/HEAD 以外）・`all`・`never`（ホスト固定は効く）。秘密を使わない `GET`・`HEAD` は確認しない（外部の文章を読んだあとの規則は、これまでどおり）。カードには、メソッド・プレースホルダーのままの URL・実際のホスト・使う秘密の id・本文の先頭を出し、値は出さない（カードは、秘密ごとの送ってよいホストは出せない：カードを作る側が登録簿を持たないため。実際の送り先ホストと「設定したホストにだけ送ります」の文を出す）。
- 道具の説明に、使える id と、その送り先を入れる。
- **限界**：Dart の `http.Client` は、名前解決した IP に接続を固定できないので、名前解決のあとの DNS の切り替え（DNS rebinding）の隙間は残る。巨大な応答を読む途中の打ち切りは、専用のテストが無い。
- テスト：`test/mcp/http_request_tool_test.dart`、`test/core/http_request_parse_test.dart`（モデルが書いた JSON からカードまで）。

## 道 B：スクリプト・`curl`（proot の中。`run_command` / `shell_session`）
`lib/mcp/placeholder_commands.dart`。
- コマンドの文字に `{{secret:ID}}` を書ける。アプリは**値を文面に入れず**、`${ARCE_SECRET_<ID>}` という環境変数の参照に書き換え、値は**そのコマンド 1 回だけ**の環境変数として渡す（`LinuxEnv.prootCommand` の `env -i`。ファイルにもログにも書かない）。
- 書き換えは置き換え位置の引用符に合わせる：引用符の外は `"${…}"`、二重引用符の中はそのまま、単一引用符の中は閉じて開き直す、`$'…'` の中は拒否。**コメントと here-document の本文は書き換えない**（値がワークスペースのファイルに書かれないように。スクリプトは `os.environ["ARCE_SECRET_<ID>"]` のように環境変数を自分で読む）。here-document の検出は字句の近似（`$((1<<2))` のような式を取り違える可能性）。
- **必ず承認**（`shellConfirm` やサンドボックスの中かどうかに関係なく）。カードに、モデルが書いた文のまま・使う秘密 id と送ってよいホスト・文面のアドレスを出し、アドレスが無いときは「**宛先を確かめられません**」と出す。履歴には、書き換える前の文が残る。
- **文面のアドレスの検査**：使う秘密すべての送ってよいホストに入っていなければ**実行しない**（`http://`・他のスキーム・`user@host`・読めないホスト・ホスト部のプレースホルダー・curl 等へ渡す `https://` なしのホスト）。
- 出力・活動の文・session の画面から値を取り除く。session の `send` で使えるのは、その session を始めたときに渡した id だけ。
- **旧方式の `secrets: [NAME]`**：環境変数 `名前` として値を渡す（モデルは名前だけを知る。`run_command` の説明に並ぶ）。使える名前は、値があるものだけ。使えない名前を書くと、**実行せずに**「使える名前はこれ」と返す。`secrets` が空でないコマンドは、**サンドボックスの中で済むものでも、必ず承認カードを出す**（`shellConfirm` がオフでも。`secrets` の形が崩れていても確認する）。カードに「**秘密を渡します: 名前…（このコマンドは、これらの値を読めます。送り先は制限できません）**」。「次から確認しない」は、コマンドには出ない。名前は Dart と Kotlin の両方で検査する（英数字と `_`、先頭は数字以外、64 文字まで。`HOME`・`PATH`・`LD_PRELOAD`・`BASH_ENV` など、アプリが決める／読み込みを変える名前は不可。`ShellSecrets.validName`）。出力に渡した値がそのまま出ていたら `[名前]` に置き換える（4 文字以上の値だけ）。設定（Linux 環境 →「コマンドで使う秘密」）：環境変数の名前と、値のもと（入力した値（`shell_secret.<名前>`）／登録してある MCP サーバーのトークン）。設定の JSON には**名前と、もとの MCP サーバーの id と、ホストだけ**が入り、値は入らない。`secrets` に id を書いても `ARCE_SECRET_<ID>` として渡る（併用できる）。**チャットからは、秘密の一覧を変えられない**（`blocked` の `shellSecrets`）。
- **限界**：スクリプトファイルの中・プログラム自身が決める宛先・値を変形して送る行為は検査できない（カードの注意書きだけ。**道 A のような宛先の保証は無い**）。防げるのは、うっかり環境変数を表示したときだけで、意図的な持ち出し（変換して出す・ネットワークで送る）は防げない。**承認の前にコマンドを読むこと**が唯一の歯止めで、画面にもそう書いてある。

## 脅威と、扱い

| 脅威 | 道 A | 道 B |
|---|---|---|
| 注入された指示が、キーを別のサーバーへ送らせる | **断る**（ホスト固定） | 文に書かれた URL は断る。**スクリプトの中は防げない**（承認で止める） |
| リダイレクトで別のホストへ | **同じホストだけ**追う | 防げない |
| 応答がキーをそのまま返す | 伏せる | 伏せる（変換されたものは防げない） |
| 端末内のアドレス（SSRF） | 秘密を使うときは断る（DNS rebinding の隙間は残る） | 防げない |
| 履歴・ログへの漏れ | 履歴は、プレースホルダーのまま | 同じ |
| 利用者の見落とし | カードに、ホストと秘密の名前 | カードに、秘密の名前とホスト。中身の検査ができないことを書く |

## 設定（すべて設定。`secretsOffForModel`・`httpRequestConfirm`・`httpRequestAllowInsecure` はチャットから変えられない）
`httpRequestEnabled`・`httpRequestConfirm`・`httpRequestMaxResponseChars`・`httpRequestTimeoutSeconds`・`httpRequestAllowInsecure`（http。既定オフ）・`httpRequestMaxRedirects`・`secretsOffForModel`、秘密ごとの `hosts`（`shellSecrets` の中）。

## 既存の仕組みとの比べ
同じ考え方のものがある：[Infisical Agent Vault](https://github.com/Infisical/agent-vault)（MIT。Go。通信に割り込む HTTPS の proxy。README に Preview とある）、[CrimsonWorks agent-vault](https://github.com/CrimsonWorks-Inc/agent-vault)（Apache-2.0。Node。送信直前の差し替え。「M0/M1」とある）、[1Password CLI の `op://`](https://developer.1password.com/docs/cli/secret-references/)（`op run`。1Password の契約が前提）。**そのまま取り込むのは、しない**（どれも別のホストや別のデーモンで動く前提で、Android の proot に CA 証明書を入れる作業も要る。未成熟とも書かれている）。参考にするだけにした（利用者の判断）。参考にして入れたのは、値を伏せてから切ること・切れた末尾を落とすこと・伏せる形の追加。Infisical の文書（infisical.com）は、この環境のネットワークで開けず、GitHub の README だけを読んだ。
- **まだ入れていない案**（参考にした作りにあるもの。利用者の判断待ち。`open_questions`）：秘密ごとに「差し込める場所」を決める（ヘッダだけ、など。本文やパスに入れると、許可したホストの中で別の場所に値を書き込めてしまう）／秘密ごとのパス・メソッドの範囲／使う回数の上限／プロバイダ用の「鍵を作る管理用のパス」の拒否。
