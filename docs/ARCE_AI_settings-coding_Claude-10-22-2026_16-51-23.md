# 設定の整理、履歴検索、コーディングモード（2026-10-22 JST）

## 1. 機密情報以外は全て設定できる

- 設定できないのは **APIキー・GitHubトークン・MCPトークン** だけ（安全な領域に保存。設定JSON・バックアップ・チャットには出ない）。
- これまで固定だった値を設定にした：添付（ファイル数・文字数・画像のMB）、検索結果の件数、通信・MCP・オンラインモデルのタイムアウト、ツールの繰り返し検出、更新ダウンロードの試行回数と無通信の判定、ローカルのDRY。
- プロバイダに、編集画面がなかった **ツール呼び出しの対応・追加ヘッダー・追加のリクエスト項目（JSON）** を足した。機密になりうるヘッダー名（`Authorization`・`x-api-key`・`token`・`secret`・`cookie` など）は断る。
- モデルごとに **画像を送る** スイッチ（未設定のモデルは名前から推測）。
- チャットの `update_settings` でも、上の設定を変えられる（`lib/core/settings_spec.dart`）。`autoInstallUpdate` が漏れていたので足した。
- 方針は `AGENTS.md` と仕様書12章に書いた：**コードに固定の数字を足すときは、設定も足す**。

## 2. ローカルとオンラインで別々のモデル設定

| | ローカル（端末のモデル） | オンライン |
|---|---|---|
| 項目 | temperature・top_p・top_k・min_p・DRY・最大トークン・追加プロンプト | temperature・top_p・最大トークン・追加プロンプト |
| 空欄 | アプリの既定（-1 / 0 / 空） | 同じ |
| 優先 | 設定 > 既定 | モデルごとの設定 > ここ > 既定 |
| 端末専用 | コンテキスト長・スレッド・HyperLoad・GPU・KVキャッシュ・Force Execution | — |

`AppSettings.toGeneration(modelParamsB, cloud: engine.isCloud)` が、いま答えるモデルの側を選ぶ。片方を変えても、もう片方には届かない（テスト：`test/services/settings_test.dart`）。

## 3. 設定画面：のれん式

- 押した項目だけが、その下に開く（`AnimatedSize`）。ほかの項目は混ざらない。別の項目を押すと、開いていたものは閉じる。
- サイドバーなど外から開くときも、その項目だけを開く（`AppController.openSettings`）。
- 以前は、1つの縦長の画面に全項目を並べて、押した項目の位置へスクロールしていた。これが「ほかの設定が混ざる」原因だった。
- Thinking アイコンの「基本」「ドット」は、アイコンとドットを1つのグループとして中央に置く（以前はドットが外にはみ出して、全体が中央からズレていた）。

## 4. ハンバーガーメニューとチャット履歴の検索

- 左上のハンバーガー：スマホはドロワー、デスクトップはサイドバーの開閉。
- 検索は、**タイトル**（大文字小文字を区別しない）と、**本文**（全文検索。3文字未満は `instr()`）。結果は会話ごとに1件にまとめ、一致した行を強調する（`lib/services/conversation_search.dart`）。
- 同じ部品（`HistoryPanel`）を、ドロワーとサイドバーで使う。

## 5. コーディングモード（設計モデル＋開発モデル）

Cline のように、**設計モデルが開発モデルに指示し、複数のモデルで分担して安く実装する**。

```
依頼（Coding エージェント）
  └ 設計モデル：JSON の計画（要約 + タスク）を返す  ← 高性能・短い出力
       ├ 開発モデル：タスク1 ┐
       ├ 開発モデル：タスク2 ├ 同時に書く（設定の数まで。端末のモデルは1つずつ）
       └ 開発モデル：タスク3 ┘
  └ 設計モデル：結果をレビュー → 直すところがあれば、そのタスクだけ書き直させる（回数は設定）
  └ 計画の順に結果を並べて返す
```

- 安くなる理由：長いコードを書くのは開発モデル（安い・端末のモデルなら無料）。設計モデルの出力は短い計画とレビューだけ。開発モデルには、会話の全体ではなく **依頼・計画の要約・そのタスク** だけを送る。
- 設計モデルが JSON の計画を返さないとき（質問・小さな依頼）は、その答えをそのまま返す。開発モデルは呼ばない。
- 1つのタスクが失敗しても、ほかの結果は返す。止めると、以降のリクエストを送らない。
- 使うのは、Coding エージェントの **新しい返信** のときだけ（続きは元のエンジンのまま）。オフ・役のモデル未選択・端末のモデル未読み込みのときは、いつもどおり1つのモデルで答える。
- 役にはオンラインの各モデルも、端末のモデルも選べる（`provider|model`、端末は `local|`）。
- 設定：オン/オフ、設計モデル、開発モデル、タスクの最大数（既定4）、同時数（既定3）、レビュー回数（既定1。0でレビューなし）、役ごとの最大トークン。チャットの入力欄に「分担」ボタン。
- 実装：`lib/core/coding_plan.dart`（計画・レビューの読み取りとプロンプト）、`lib/ai/coding_engine.dart`（`CodingEngine`・`ProviderRole`・`LocalRole`）、`RoutingEngine.coding`。

## 6. 確認したこと／していないこと

- 確認：`flutter analyze` と `flutter test`（303件）。分割・並列数・差し戻し・レビュー回数・中断・失敗・計画が JSON でないとき、設定の保存と範囲、画面（アコーディオン・ドロワー・検索・サイドバー）。
- 未確認：**実際のオンラインモデルでの設計→開発→レビューの往復**（偽のモデルでの確認まで）。モデルによっては JSON の計画を守らないことがある（そのときは設計モデルの答えをそのまま出す）。端末のモデルを開発役にした実機での動作。
- 既知の制限：開発モデルの出力は、全員が終わってから計画の順に出す（途中経過は「設計」「開発:」「レビュー」の行だけ）。トークンの使用量・費用の表示はまだない。
