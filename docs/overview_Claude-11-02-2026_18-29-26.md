# 概要・ディレクトリ・作業のルール・履歴

現行の仕様だけを書く（1.0.1 時点）。リポジトリ：`keusidan/arce.ai`。ブランチ・コマンド・壊すと困る約束は `AGENTS.md`（ツールがファイル名で読み込むので、別ファイルのまま）。

## 何のアプリか
端末の中だけで動くローカル AI のチャット / コーディングアシスタント。Android・iOS・Windows・macOS・Linux で同じ画面が動く Flutter 製。推論エンジンは **Android だけ**（llama.cpp と LiteRT-LM）。他の OS は、固定のデモ応答を返す `DemoEngine` で、画面・履歴・設定・更新機能だけが動く。ローカルの推論に加えて、オンラインのモデル（OpenAI 互換のプロバイダ）も、同じ立場の「エンジン」として使える（`providers`）。企画は `requirements`、実装上の失敗の教訓は `lessons`。

## 作業のルール（利用者の指定）
`AGENTS.md` に、壊すと困る約束がまとまっている。ここには、その背景と、AGENTS.md に載せていないものを書く。
- 返答は日本語。時刻は**日本時間**で書く。略称は初出で「略称(正式名称)」。英語由来の技術用語は英単語のまま。説明には出典を付ける。
- 新しい docs のファイル名の末尾に `Claude-MM-dd-yyyy_HH-mm-ss` を付ける（既存のファイルの編集は元の名前のまま。ツールがファイル名で読むもの — `AGENTS.md`・`README.md` など — は付けない）。コードのファイルには付けない。
- PR は、頼まれるまで作らない。push するブランチは利用者が指定する（通常は `dev`）。ブランチは、頼まれるまで作らない・消さない。`archive` には push しない。
- コミットの末尾に、Co-Authored-By と Claude-Session の 2 行（セッションごとに指示される値）。
- 署名鍵（`*.jks`）をリポジトリに入れない（`.gitignore` 済み）。
- **すべての版を 5 つの OS で確かめる**（`release_ci`）。5 つのリリースは、それぞれ別の workflow で**並行**に動く。OS 間に `needs:` や `workflow_run` を置かない。
- 外部から patch やコードを取ってきて当てる workflow、コミットを push する workflow は作らない（`bot.yml` だけが、限度つきの例外。`github_bot`）。
- 機密情報以外は、すべて設定にする（`settings_policy`）。
- **利用者の指示の扱い**：利用者の指示を時系列で書き写した記録は、持たない（1.0.0 で現行の仕様だけにした）。**今も効いている指示は、このファイルの「作業のルール」と `AGENTS.md`、各ファイルの仕様に書く**。指示を受けて仕様が変わったら、そのファイルを直す。1.0.0 より前の、指示の原文・時刻・対応した版の記録は、`archive` ブランチの `docs/ARCE_AI_docs_Claude-10-26-2026_02-16-25.md`（19 章）にある。
- 利用者の判断（初期のレビューで決めた）：非公開・個人利用のためライセンス対応は不要（ただし GPL / AGPL の部品を同梱するときは別。`linux_environment`）、Google Play Store には出さない、EXE の生成は対象外、Termux 関連は実装しない。
- コードを書くときは、周りのコードに合わせる（コメントの量・名前・書き方）。テストは `test/core` で Kotlin の `core/` に対応させ、`lib/core` を変えたら対応するテストも変える。テストは、モデルが書いた JSON を読む経路を通す（`test/core/protocol_test.dart` など。新しい引数を足すときは、パーサを通すテストを必ず書く）。
- 大きな塊（KV キャッシュ、モデルのファイル）はファイルに置き、索引だけを SQLite の `assets` に持つ（`storage`）。
- モデル固有の既定値（`lib/ai/model_hints.dart`）は、メーカーが公表したモデルカードだけを根拠にする（`providers`）。
