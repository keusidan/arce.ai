# 画面の仕様

現行の仕様だけを書く。経緯・修正の履歴は書かない（1.0.0 より前の履歴は `archive` ブランチにある。`overview` の「履歴」参照）。**未確認**と書いたものは、実機で確かめていない。

## 配置とページ
- 幅 900px 以上はデスクトップ配置（左サイドバー 280px、上バー 56px）、未満はスマホ配置（上のヘッダー＋下のナビ 4 つ）。`lib/ui/shell.dart`。左上のハンバーガーが、スマホではドロワー（履歴の検索つき）を、デスクトップではサイドバーの開閉を担う。
- ページ（`AppPage`）：チャット、モデル管理、生成物、詳細設定、チャット履歴。ヘッダーに設定アイコンは無い（下のバー・サイドバーに「設定」がある）。
- 文字：Noto Sans JP を同梱している（日本語の字形が中国語の字形にならないように）。**文字の大きさ**（`fontScale`、0.7〜2.0。設定の選択肢は 85〜200%）は、アプリ全体に効き、端末の文字サイズの設定に**重ねて**効く（端末 130% × アプリ 150% で約 195%）。大きくしても上下のバー・メニュー・設定の行があふれないこと（`test/ui/text_scale_test.dart`）。

## チャット
**表示**
- 返信は、アイコン・名前・エージェント名・時刻・吹き出しの枠が無い。思考・ツールの表示・本文・操作ボタン（コピー・再試行・続行）を、上から幅いっぱい（最大 920px）に並べる。ユーザーの発言だけが吹き出し（右寄せ、幅は画面の 88% まで）。左右の余白は 12。
- 部品：歓迎画面（4 つのチップ）、思考プロセス（折りたたみ）、ツールの結果（検索はリンク付きで折りたたみ）、`ask_user` の質問カード、承認カード、エラーと注意の帯。生成中は「考えています…」のカード（エージェント名は出さない。アイコンは 5 種（基本・リング・パルス・ドット・ローテーション）から設定で選ぶ）。
- 入力欄：ファイル添付（画像と UTF-8 のテキスト。`storage`）、思考・検索・分担（コーディングモード）のスイッチ、送信/停止。モデルのボタンは無い（モデルの管理は下のタブとヘッダーのモデル名から）。デスクトップは Enter で送信、Shift+Enter で改行。
- 入力欄はすべて `ArceTextField`（`lib/ui/arce_text_field.dart`）から作る。予測変換・自動修正・キーボードの学習をオンにする。例外は**秘密**（`obscure`：API キー・トークン）だけで、隠した文字はキーボードの辞書に渡さない。`TextField(` を直接書いたり `enableSuggestions: false` を足すと、`test/ui/arce_text_field_test.dart` が落ちる。
- 編集画面（プロバイダ・モデル・MCP・検索 API）：下から出るシートの下の余白は、キーボードの高さかシステムのバーの高さの大きい方（`sheetBottomPadding`）。3 ボタンのナビゲーションバーが「試す」「保存」に重ならない。
- コーディングモードのモデル選択：欄を押すと画面の幅いっぱいの一覧が下から開き、名前を省略せずに書く。

**Markdown**（`lib/core/markdown_lite.dart` が読み、`lib/ui/chat_widgets.dart` の `RichReply` が描く）
- 描くもの：見出し（`#`〜`######`）、**太字**・*斜体*・~~取り消し線~~・`コード`（入れ子もよい）、リンク（`[文](https://…)` と、文中の http(s) のアドレス。タップでブラウザ）、箇条書き・番号つき・タスクリスト（字下げで入れ子）、引用、区切り線、表（`|---|` の行が届いたら表。列の揃え `:--:` に対応。幅が足りなければ横にスクロールし、1 セルは最大 280）、コードブロック。
- 描かないもの（そのまま文字で出す）：HTML、画像、脚注、LaTeX、setext 見出し（`===`）。
- リンクは **http(s) だけ**開く（`safeWebUri`、`lib/core/safe_url.dart`）。`javascript:`・`intent:`・`tel:`・`sms:`・`file:`・`content:` と、ユーザー名つきのアドレス（`https://good.example@evil.example/`）は、リンクにしない。アップデートの Release ページも同じ。
- ストリーミング中の途中の記法（閉じていない `**` や `` ` ``、表の区切り行の前）はそのまま見え、閉じたら記法になる。
- モデルに求める形は普通の Markdown だけ（`ChatMlPromptBuilder.baseSystemPrompt`：リスト・太字・比較には表・見出しは長い回答だけ・プログラムやファイルは言語つきのコードブロック）。アプリ独自の書き方は強いない（独自なのは、端末のモデルが `<tool_call>` で道具を呼ぶ形（Qwen の標準）と、` thinking` の思考だけで、どちらも本文ではない）。
- コードブロック：見出しのタップで折りたたみ/展開（折りたたむと `python · 20行`）。14 行を超えると下にも「折りたたむ」「コピー」が出る。設定 `codeFoldLines`（既定 0＝折りたたまない）で、長いブロックを最初から折りたたむ。書いている途中のブロックは、いつも開いている。`>` の引用は、3 行以上か 80 文字以上のとき「コピー」が出て、`>` を外した元の文章を写す。
- **HTML・SVG のコードブロック**は、見出しの「表示」で、コードの下に**チャットの中で**表示できる（`EmbeddedPage`、`lib/ui/embedded_page.dart`。高さは設定 `inlinePreviewHeight`、既定 360、0 で「表示」のボタンを出さない）。もう一度押す（「閉じる」）と閉じる。HTML の見出しには、システムのブラウザで開く「ブラウザ」もある。SVG は、白い背景の素のページに置いて表示する。
  - **描くもの**：5 つの OS とも WebView（部品 `webview_all` 1.4.9、MIT。Android の WebView・iOS と macOS の WKWebView・Windows の WebView2・Linux の WebKitGTK）。**描くものは差し替えられる**：`EmbeddedPage.builder` に、アドレスと高さから部品を作る関数を入れると、WebView の代わりにそれが使われる（テストと、将来のほかのビューアの口）。
  - **ページの元**：`PreviewServer`（127.0.0.1）が出す。
  - **ページからの移動**：ページは同じアドレスの中だけ。ほかのアドレスへの移動は止め、web のリンクはシステムのブラウザで開く（`safeWebUri`）。
  - **起動できないとき**（WebView2 が無い PC、WebKitGTK が入っていない Linux など）：「このアプリの中では表示できませんでした」と出し、「ブラウザで開く」を出す。
  - **Android**：WebView は、標準では http を拒否するので、`network_security_config.xml` で、`127.0.0.1` と `localhost` だけに http を許す（アプリ自身の通信（dart:io）には効かない）。
  - **自動で開く**：設定 `autoShowPages`（既定オフ。**チャットからは変えられない**：モデルが書いたページを、ボタンなしで動かすため）をオンにすると、ページは書き終わったときに 1 回だけ自動で開く（閉じたら、また自動で開くことはない）。
- **道具 `show` が出すカード**（`arce-view` ブロック。`lib/core/page_blocks.dart`）：モデルが道具 `show`（`html`・`svg`・`path`・`port` のどれか 1 つ。`title`・`url_path`）を呼ぶと、返信にカードが入る。カードは**コードではなくページの札**で、題（無ければ「ページ（HTML）」「/workspace/…」「127.0.0.1:ポート/パス」）と「表示」「閉じる」「ブラウザ」のボタンだけを出す（JSON は見せない・コピーも無い）。ブロックは返信の本文に入るので、会話といっしょに保存され、開き直しても同じカードになる。
  - **ページの元**：`html`・`svg` はページそのもの（ブロックの中。バッククォートは `\u0060` に書き換えるので、ページの中の ``` で囲みが閉じることはない）。`path` は `/workspace` の下のファイルか、`index.html` のあるフォルダ（`.html`・`.htm`・`.svg`・画像だけ。隠しファイル（`.` で始まる名前）と、`/workspace` の外へ出るリンクは断る）。フォルダのページは、そのフォルダの中だけから配る（`PreviewServer.publishFolder`：隣のスタイル・スクリプト・画像も出る。ファイルは設定 `showMaxFileMb`（既定 20）まで。`..`・隠し・リンクで外へ出るものは 404）。`port` は、この端末（127.0.0.1）の 1024〜65535 の、いま応えているポート（`show` は、つながるかを先に確かめ、つながらなければ、モデルに「`shell_session` で動かし続けてから」と返す）。
  - **安全**：`show` は、カードを返信に入れるだけで、何も開かない（承認は要らない。開くのは利用者のボタン）。ブロックの中身は、モデルが書いた文として読み直すので、**開く前に毎回検査する**（ポートの範囲・パスの形・`..`・ホストを含む書き方）。通らないブロックは、ふつうのコードとして見える。ページは、いつものとおり、独立した領域（`sandbox`）で動く。
  - **設定**：`showEnabled`（道具を出すか。既定オン）、`showMaxChars`（`html`・`svg` を直接渡せる長さ。既定 200000）、`showMaxFileMb`（既定 20）、`inlinePreviewHeight`、`autoShowPages`。
  - **ビューアの入れ替え**：`port` で出す先は、「127.0.0.1 のポートで HTTP を出す」ものなら何でもよい。Linux 環境（proot）の中で、`shell_session` で動かし続けた HTML ビューア・簡単な Web サーバー・Python の画面など（`shell_sessions`）が、そのまま、中身の入れ替えだけで見える。アプリが決めているのは、「どのポートの、どのパスを見せるか」だけ。
- ブラウザで開く方（「ブラウザ」）は、`PreviewServer`（127.0.0.1）経由でシステムのブラウザに表示する。ページの入口は **128 ビットの乱数**で、`Host` が `127.0.0.1` でない要求（DNS リバインディング）は断り、`Cache-Control: no-store`・`Referrer-Policy: no-referrer` を付け、残すページ数に上限（設定 `previewMaxPages`、既定 50）がある。

**思考の見え方**
- 考えている間は、見出しに経過の秒数（`考えています… 12秒`）、思考の本文が下の枠に流れ込み、新しい行に追従する（高さは 190 まで。読むために上へ戻すと追従を止める）。終わると見出しが「思考（12.3秒）」になり、本文は設定「思考の内容を開いたまま表示」に従って開く/閉じる（高さは 340 まで）。見出しのタップで折りたたみ/展開でき、読む人が開け閉めした状態が優先。
- 思考の長さは `UiMessage.thinkingMs`（最初の思考の文字から、返信の最初の言葉・道具の呼び出し・終わりまで）と、思考中の印 `thinkingSince`（0 なら思考中でない）で持ち、履歴にも保存する（思考の部分の payload に `ms`）。思考の本文が届き始めたら、回るアイコンのカードはこのブロックに替わる。プロバイダが思考を送らないモデル（`reasoning_content` なし）には出ない。
- 道具を呼ぶラウンドをまたいでも、思考は前のラウンドの後ろに続けて足す（置き換えない）。

**返信の進み具合**（`lib/core/run_progress.dart`：`RunProgress`・`RunMeter`・`ThinkingHeadline`。`ChatState.progress` 経由で画面に届く。保存しない）
- 返信している間、最後の返信の下に状況の枠（`RunStatus`）が出る。1 行目はいまの段階（「プランナーが考えています」「検索しています」「開発モデルが作業しています（1/3 件完了）」「プランナーが回答を書いています」。分担のときだけ「プランナー」、ほかは「モデル」）、2 行目は詳しい 1 行（思考のときは、モデルが最後に書いた見出し（`**…**` や `## …`）か最後の行。検索の語。作業中のタスクの名前）、3 行目は数字（`2 回目の返信 · 通信 5 回（プランナー 3・開発 2） · ツール 1 回 · 1:24`。時計は 1 秒ごと）。
- **最初の言葉が来るまで**は、「モデルに送信しています（返信を待っています）」と出る。**送る指示が約 3,000 トークン以上のとき**は、指示の大きさと「端末のモデルでは、最初にこれを読み込むので、数分かかることがあります」を添える（`ChatController.slowPromptTokens`。端末のモデルは、答えの最初の 1 語の前に、指示を全部読むので、画面に何も出ない時間が長い。思考の文字は、読み込みが終わってから流れ始める）。
- 終わると 1 行の薄い字（`通信 5 回（…） · 所要 1:24`）だけが残り、別の会話を開く・新しい会話にすると消える。数えるもの：通信＝モデルへの要求（再生成・空の返信のやり直しも 1 回。開発モデルへの要求は 1 タスクごと。フォールバックで別のモデルへ切り替わった分は数えない）、ツール＝道具を実行した回数。`DelegateRunner` も `RunMeter` を受け取って、開発モデルの進み具合を知らせる。

**空の返信**：本文も道具も無く、前の道具の結果の表示も無い返信は、`retryLimit` 回まで同じ要求をやり直す。それでも空なら「プランナーの返信が空でした」、思考だけで出力の上限（`length`）に達したときは「最大トークンを増やすか思考を弱めてください」と画面に出す（再試行ボタン付き。空の返信は自動報告の対象）。道具のラウンドが終わるごとに、そこまでの返信を履歴に保存する（長い分担の途中でアプリが閉じられても残る）。

**タイトル**（設定 `autoTitle`・`titleModel`・`titleMaxChars`（既定 30））：新しい会話の最初の答えが終わると、モデルが最初の質問と答え（先頭 600 文字ずつ）から短いタイトルを考え、履歴に付ける（`TitleMaker`。思考は切る指定つき。引用符・「タイトル:」・Markdown の印・末尾の句点は外し、最大文字数で切る）。使うモデルは設定「タイトルを考えるモデル」（`provider|model`。安いモデルにできる）、空なら使用中のオンラインモデル。**端末のモデルでは自動では付けない**（タイトルの依頼が KV キャッシュの会話を押しのけ、次の返信が最初から読み直しになるため。タイトル用にオンラインのモデルを選べば付く）。付くまでと、失敗したとき（最大 2 回試す）は、最初の質問がタイトルのまま。開いた会話や、中断から続ける会話には付け直さない。

## 会話の同時進行・停止・割り込み
- **生成中でも別のチャットへ移れる**：会話ごとに `ChatController` があり（`AppController` の `_Session`）、画面に出ているチャットを離れても、生成中のチャットは裏で続けて保存まで終える。画面は窓口の `ChatHandle`（`lib/services/chat_handle.dart`。常に同じオブジェクトで、中身の向き先だけが変わる）を通して表のチャットを見る。履歴の一覧には、生成中の会話に「生成中」の印が出て、タップすると裏のチャットがそのまま表に出る。前面サービスは、どれかが生成中の間は動かす。
  1. **オンラインのモデルは同時にいくつでも**答えられる。「停止」はそのチャットだけに効く（共有の `CloudEngine` には cancel を送らない。送ると他のチャットの返信まで止まる）。
  2. **端末のモデルと分担（コーディングモード）は同時に 1 つのチャットだけ**（重みと KV キャッシュが 1 つのため）。使用中に別のチャットが送ると「ほかのチャットが使っています」とエラーを出す（`SessionEngine`、`ExclusiveLease`。`lib/services/session_engine.dart`）。
  3. 生成中の間は、モデル（プロバイダ）の切り替えは断る。
  4. 生成中のチャットの会話を削除すると、その生成を止めてから消す。
  5. 「生成中」の判定は `ChatController.isRunning`（返信の途中の、エージェントを選ぶ・MCP に聞く間も含む）。
  - **未確認**：実機での、オンラインの 2 つのチャットの同時生成と、端末のモデルの排他。
- **停止はすぐに効く**：`GenerateRequest.abort` / `AiRequest.abort`（停止で完了する Future）を持ち、`OpenAiCompatibleProvider` は `http.AbortableRequest(abortTrigger)` で送り、停止されたら接続を切って「止めた」で終える（`RequestAbortedException`）。`SessionEngine` は、停止の合図と次のデータを競わせ、先に合図が来れば待たずにストリームを閉じる。返信の準備中（エージェントを選ぶ、MCP の道具の一覧を聞く、道具を実行する）に押した停止は、`ChatController._stopRequested` が覚え、次のリクエストを送らずに「止めた」で終える。端末のモデルは、エンジンが次のトークンで気づいて止まる（長いプロンプトの評価中は少し待つことがある。**未確認**）。
- **途中送信**（`ChatController.interject / unqueue`、`ChatState.queued`）：返信の最中も入力欄は使える。文を書いて「割り込む」（デスクトップは Enter）を押すと、文は入力欄の上に「次の区切りで伝える: …」と出て（✕で取り下げられる）、今動いている道具は止めずに、その道具が終わった次の区切りで、モデルに別のユーザーのメッセージとして渡る（履歴は 道具の結果 → 割り込みの文 の順。画面では、それまでの返信はそこで区切られ、新しい返信が続く）。道具を使わないまま返信が終わったときは、残っている文が次のメッセージとして自動で送られる（止めたときも同じ。エラーや質問で止まったときは入力欄の上に残る）。複数の文は 1 つのメッセージにまとめる。ファイルの添付は割り込みでは送れない（返信が終わってから）。長い分担の仕事（`delegate`）の途中では、その仕事が終わるまで割り込めない（道具の区切りだから）。
- **前面サービス**：`GenerationService` は「まだ応じていない開始の数」を持ち、その間に来た停止は覚えておく。`startForeground()` を呼んだあとで、覚えていた停止を実行して自分で止まる（`startForegroundService()` のあとに `startForeground()` が呼ばれないと Android がアプリを落とすため。[Context.startForegroundService](https://developer.android.com/reference/android/content/Context#startForegroundService(android.content.Intent))）。**未確認**：実機で、承認カードの「実行する」を押してもアプリが落ちないこと。

## 承認カードと許可記憶
- 道具を実行する前の確認は `ToolApprovalCard`。**道具**は「server · tool」で名前を出し、引数を 1 つずつ、長い値は 240 字で切って全部で何文字かを添え、「全文を見る（N 文字）」で開く（スクロールできる等幅の箱で全文）。**コマンド**は `$ コマンド` をそのまま、場所と最大秒数。確認する理由が分かりにくいとき（外部の結果を読んだあと）は、カードに理由が出る。秘密を使うコマンド・`http_request` のカードは `secrets` を参照。
- ボタンは「実行する」「実行する（この道具は次から確認しない）」「やめる」。押した瞬間にカードが消えて、画面に「ツールを実行しています」が出る。ボタンは 1 回だけ答える。道具が例外で終わっても、失敗として結果をモデルに伝える（返信全体は落ちない）。
- **許可記憶**：「次から確認しない」を選ぶと、道具の名前（`mcp_server__tool`）が設定 `approvedTools` に入り、以後その道具は聞かない。**対象は MCP の道具だけ**（コマンドは何をするかがコマンドで決まるので、記憶できない）。設定ファイルに `approvedTools` として `run_command` などを書いても、読み込むときに外す。外すのは、設定 → MCP サーバー →「確認しない道具」の ✕。チャットからは見ることも変えることもできない（`blocked`）。

## 通知（Android のみ。`NotifyBridge.kt`、チャンネル `ai.arce.app/notify`）
- 返信が**許可・答えを待って止まった**とき、**終わった**とき、**失敗した**ときに、システムの通知を出す。種類ごとに設定（`notifyNeedsYou` / `notifyDone` / `notifyFailed`、既定はすべてオン）と、`notifyOnlyAway`（既定オン＝そのチャットを画面で見ているときは出さない。アプリが前面でも別のチャットの返信なら出す）。
- 判定は `ReplyWatch`（返信が動いていた状態から止まったときだけ。保存した会話を開いただけ・停止・途中の段階では出さない）。設定をオンにすると、Android 13 以降は通知の許可を聞く。「確認・失敗」は音の出るチャンネル、「完了」は通常のチャンネル。同じ会話の通知は 1 つに置き換わる。
- 通知を押すとアプリが開くだけで、その会話までは開かない。iOS・デスクトップは何もしない。**未確認**：実機での通知。

## 思考のレベルのスライダー（入力欄の「思考」ボタンの隣。`lib/ui/thinking_level_slider.dart`）
- **オンラインのモデル**：段階のスライダー。段階は、メニュー（「思考」ボタン）と同じで、オフ・自動と、そのモデルの送り方が名前を持つ強さ（OpenAI・OpenRouter・chat template の形は 低・中・高、DeepSeek・Z.ai の形は 低・高・最大）。離したときに、そのモデルの思考の設定（`ThinkingConfig`）へ保存する（メニュー・詳細の設定と同じもの）。右に、いまの段階の名前が出る。「常にオン」や数字の強さは、つまみは「自動」の位置に立ち、名前だけがそれを言う。
- **思考の送り方が未設定のモデル**：何も送らないので、動かすものが無い。スライダーは灰色で、「未設定」と出る。押すと、送り方を決めるメニューが開く。
- **端末のモデル**：速度⇔精度（0〜1、20 分割）。25% 未満、または思考のスイッチがオフのときは「オフ」と出す。
- 幅が足りないときは、ほかのボタンと同じく折り返す（文字を大きくしても溢れない。`test/ui/text_scale_test.dart`）。

## 送る前のトークン数
入力欄の下に、`約 12,340 トークン（会話 8,000・入力 340・指示 1,500・道具 2,500）／文脈 131,072（9%）` を出す。入力中の文（添付ファイルの文字も）を数に入れる。文脈の 80% を超えると琥珀色、超えると赤。実際に送る文と同じ部品から作る（`ChatController.promptParts`：指示・道具の定義（MCP も）・会話・入力）。数え方は目安（UTF-8 のバイト数の 1/3。`ModelHints.estimateTokens`）。文脈の大きさは、オンラインのモデルで、分かっているときだけ（端末のモデルは出さない）。入力が止まって 0.35 秒後に数え直す。

## 生成物・モデル管理・履歴
- **生成物**：会話の中の完成したコードブロックの一覧（コピー・保存・HTML プレビュー）。無いときはサンプルを出す。
- **モデル管理**：現在の状態、基本モデルの 1 タップ導入、カタログ、ダウンロード（一時停止・再開・SHA-256 検証・整合性チェック・削除）、ファイルからの取り込み、メモリ不足の警告。Android 以外ではカタログを表示するだけ。
- **チャット履歴の検索**：タイトル（大文字小文字を区別しない）と本文（全文検索。3 文字未満は `instr()`）。結果は会話ごとに 1 件にまとめ、一致した行を強調する（`conversation_search.dart`）。同じ部品（`HistoryPanel`）を、ドロワーとサイドバーで使う。

## 詳細設定の画面
- 最初の画面は、**項目のボタンを横 2 列（縦は自動）に並べたグリッド**（アイコン・題名・短い説明）。同じ行の 2 つのボタンは、行ごとに `IntrinsicHeight` と `Expanded` で、高いほうに揃えて同じ高さにする（`Wrap` だと説明の行数の違いで下端がずれる）。
- ボタンを押すと、**その項目だけの画面に移る**（`SettingsPage` が今の項目を持ち、画面を入れ替える。戻るボタンと、システムの戻る（`PopScope`）で一覧に戻る）。自動で下へ追尾するスクロールは無い（項目の画面は、いつも一番上から始まる）。サイドバーなど外から開くときも、その項目の画面を直接開く（`AppController.openSettings`）。
- **検索**：グリッドの上の検索欄。入力すると、グリッドの代わりに全項目の行から合う結果が並び（所属の項目名・行の題・説明）、結果を押すと、その項目の画面に移る。消すとグリッドに戻る。`lib/core/settings_search.dart`：表記ゆれを揃える（大文字小文字・全角半角・カタカナとひらがな・`_ - ・` を無視）。空白で区切った語はすべて含む（AND）。題 > キーワード > 説明の順で高く、完全一致・先頭一致に加点。あいまい検索はしない。`lib/ui/settings_index.dart`：全行の索引（題と説明は画面の文字のまま、同義語のキーワード、設定のキー）。**画面の文字を変えたら、索引も直す**（`test/ui/settings_index_test.dart` が、索引の題が `lib/ui` の文字にあるか、チャットで変えられる設定がすべて索引にあるかを確かめて落ちる）。索引にない行：状態で変わる説明、「追加の開発モデル N」のような動的な題、チャット欄の「検索」ボタン、`batchSize`。
- 項目：プロバイダ、オンラインモデル、ローカルモデル、コーディングモード、Linux 環境（Android だけ）、上限とタイムアウト、MCP、モデル全般設定（ローカルとオンライン共通：Thinking 表示・回答の口調・速度⇔精度・エージェント・返信の長さ・最大トークン・再試行・ツール呼び出しの上限）、検索設定（SearXNG のアドレス・検索結果の件数・検索 API の一覧）、表示（文字の大きさを含む）、アップデート、エラーの報告。
- 秘密の画面（`secrets`）は「Linux 環境」の中にある。値の保存は `SettingsStore`（JSON 1 つ。キーとトークンは入らない。`settings_policy`）。
